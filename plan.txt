Build: ANIRUDH — AI-Powered Live2D Desktop Agent Pet
1. Product Vision
Build a cross-platform desktop AI companion called ANIRUDH.
ANIRUDH is a transparent, always-on-top desktop pet represented by the word:
A N I R U D H
Each letter represents an AI capability:
A — Analyze
N — Navigate
I — Interact
R — Reason
U — Understand
D — Do
H — Help
The important concept is that ANIRUDH is both the visual representation of the AI agent and the state machine controlling the AI workflow.
When the user gives ANIRUDH a task, the application determines which capability is required and routes that task to an appropriate AI model through FreeLLMAPI.
The active letter visually reacts while that model is working.

2. FreeLLMAPI Integration
All AI model access should go through FreeLLMAPI.
The application must NOT hard-code a single AI model.
Instead, implement a model-provider abstraction:
ANIRUDH
   │
   ▼
Agent Orchestrator
   │
   ▼
FreeLLMAPI
   │
   ├── Model A
   ├── Model B
   ├── Model C
   ├── Model D
   └── ...

The user provides their unique FreeLLMAPI API key during application setup.
The API key must be stored securely using the operating system's secure credential/keychain mechanism where possible.
Never expose the API key in:
frontend source code
GitHub repository
logs
screenshots
WebSocket messages
browser developer tools
client-side JavaScript bundles

3. Model Switching
ANIRUDH should support different models for different capabilities.
The user should be able to configure which FreeLLMAPI model is associated with each letter.
Default conceptual configuration:
A → Analyze model
N → Navigate model
I → Interact model
R → Reasoning model
U → Understanding model
D → Execution model
H → Help / communication model

However, do NOT assume that these must literally be different models.
The user may configure:
A → Model X
N → Model X
I → Model Y
R → Model Z
U → Model X
D → Model Y
H → Model X

or even:
A → Model X
N → Model X
I → Model X
R → Model X
U → Model X
D → Model X
H → Model X

The model-routing layer must therefore be configurable.

5. API Abstraction
Create a provider interface so that the rest of ANIRUDH does not directly depend on FreeLLMAPI implementation details.
For example:
interface AIProvider {
  listModels(): Promise<ModelInfo[]>;

  generate(request: AIRequest): Promise<AIResponse>;

  stream?(request: AIRequest): AsyncIterable<AIStreamEvent>;
}

Then implement:
class FreeLLMAPIProvider implements AIProvider {
  ...
}

The agent orchestrator should interact with:
AIProvider

rather than directly calling FreeLLMAPI.
This keeps the architecture extensible.

6. Agent Orchestrator
Create a central Agent Orchestrator.
Its responsibilities:
Receive the user's task.
Understand the task.
Determine which ANIRUDH capability is required.
Activate the corresponding letter.
Select the configured FreeLLMAPI model.
Send the request to that model.
Receive the response.
Determine the next capability.
Activate the next letter.
Continue until the task is complete.
Report success or failure.
Conceptually:
User Task
   │
   ▼
Agent Orchestrator
   │
   ├── A → Analyze → Model A
   │
   ├── N → Navigate → Model N
   │
   ├── I → Interact → Model I
   │
   ├── R → Reason → Model R
   │
   ├── U → Understand → Model U
   │
   ├── D → Do → Model D
   │
   └── H → Help → Model H


7. Dynamic Model Selection
Do NOT blindly execute:
A → Model A
N → Model N
I → Model I
...

The letter represents the current capability, while the model is a configurable implementation of that capability.
For example:
const modelRouting = {
  analyzing: "model-x",
  navigating: "model-y",
  interacting: "model-y",
  reasoning: "model-z",
  understanding: "model-x",
  doing: "model-y",
  helping: "model-x"
};

The orchestrator should resolve:
const model = modelRouter.getModelForState("reasoning");

Then:
Reasoning
    │
    ▼
Configured Model
    │
    ▼
FreeLLMAPI


8. ANIRUDH State Machine
Use the following states:
type AgentState =
  | "idle"
  | "analyzing"
  | "navigating"
  | "interacting"
  | "reasoning"
  | "understanding"
  | "doing"
  | "helping"
  | "waiting"
  | "success"
  | "error";

Map them to letters:
const stateToLetter = {
  analyzing: "A",
  navigating: "N",
  interacting: "I",
  reasoning: "R",
  understanding: "U",
  doing: "D",
  helping: "H"
};

12. Agent Event System
Keep the visual pet independent from the AI provider.
Create an event interface:
interface AgentEvent {
  type:
    | "task_started"
    | "state_changed"
    | "model_selected"
    | "model_started"
    | "model_streaming"
    | "model_completed"
    | "task_completed"
    | "task_failed"
    | "message";

  state?: AgentState;

  model?: string;

  message?: string;

  progress?: number;

  timestamp: number;
}

Example:
{
  "type": "state_changed",
  "state": "reasoning",
  "model": "configured-model-name",
  "message": "Comparing the collected information",
  "timestamp": 123456789
}

ANIRUDH receives this event and activates R.

20. Cost / Availability Handling
Because models may have different availability, latency, or limits, implement graceful fallback.
Example:
R → Preferred Model
       │
       ├── Available → use it
       │
       └── unavailable
              │
              ▼
         Fallback Model

The fallback model should be configurable.
If FreeLLMAPI returns an error:
Do not crash the application.
Show the active letter in error state.
Attempt configured fallback if appropriate.
If fallback also fails, notify the user.
Return to idle/waiting state.

24. Product Principle
The most important concept is:
ANIRUDH is not just an animated logo.
It is the visual identity and state representation of the AI agent.
The user should be able to look at the desktop and immediately understand:
What is my AI doing right now?
For example:
A → "I'm analyzing your request."

N → "I'm navigating/searching."

I → "I'm interacting with the interface."

R → "I'm reasoning about the information."

U → "I'm understanding/interpreting."

D → "I'm executing the task."

H → "I'm helping/presenting the result."

The AI model is replaceable.
The agent framework is replaceable.
The computer-use system is replaceable.
ANIRUDH remains the persistent visual companion.
